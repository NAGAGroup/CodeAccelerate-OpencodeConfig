## Step 1 — Expand and Write plan-design-guidelines.md

Write the new file at `opencode/planning/plan-design-guidelines.md`.

Start from the full existing content of `opencode/planning/plan-json-schema.md` and add a new top section **before** the existing schema content: `## Planning Best-Practices`. This section should cover:

- **Node granularity**: Each node should do one cognitive thing. Bundling multiple distinct steps (e.g., dispatch agents, synthesize findings, write subtasks) into a single node creates compounding failure points. Split into separate nodes.
- **Entry node**: Always `session-overview`. It orients the agent before any work begins. A session-specific `session-overview.md` (generated by the planning `finalize` node) must include: session goal, output artifact path, workflow-specific operating instructions, and session-specific context.
- **Guidelines node placement**: A `load-guidelines` node (pointing to this file) should be the second node in every planning DAG — immediately after `session-overview`. This ensures the agent knows the schema and planning principles before it starts building anything.
- **Loop nodes**: Add `remaining_visits` (default: 3) to any node whose `next` array includes its own ID. Surface exhaustion to the user before calling `reset_counters()`.
- **Gate placement**: Surface the full picture to the user at the gate — including agent routing assignments, if applicable. Run `agent-routing` before `review-gate`/`seed-gate`/`research-gate` so the user approves a complete plan.
- **Hardcoded node IDs in prompts**: Do NOT hardcode specific node IDs in ADVANCE sections of prompt files. Call `next_step()` with no arguments for linear nodes. The DAG plugin presents branching options at runtime. For gate nodes, present the branch options to the user and call `next_step({ next: "chosen-branch-id" })` — but only after the user explicitly selects.
- **Terminal nodes**: Omit the `next` field entirely. Call `close_session()` at the end of terminal nodes, not `next_step()`.
- **session-overview.md generation**: In every planning `finalize` node, generate a session-specific `session-overview.md` for the created session — do NOT copy a static verbatim template. Include: the session goal (from planning conversation), output artifact path (e.g. `spec.md`), workflow-specific operating instructions (e.g. "one question at a time"), and session-specific context (open questions, hypothesis, research topic, etc.).

Keep all existing schema content intact below this new section.

Update the title at line 1: `# plan.json Schema Reference` → `# Plan Design Guidelines`.

Update `session_type` enum in the schema example to also include `plan-deep-research`:
```
"session_type": "plan-generic | plan-debug | plan-collaborative | plan-deep-research"
```
