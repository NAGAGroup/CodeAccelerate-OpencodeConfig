# DAG Node Schema — Locked (Subtask 02)

Approved: 2026-03-19

## Overview

The plugin-driven DAG execution system uses two file types:
1. **Plan DAG** — immutable definition (global or session-specific)
2. **Session state** — mutable runtime state (one file per active session)

Agent parallelism is expressed inside a node's prompt file, not in the schema. No parallel node type.

---

## TypeScript Interfaces

### DagNode

```typescript
interface DagNode {
  id: string;
  type: "agent" | "gate";
  prompt: string;            // path to .md file (relative to plan JSON or absolute)
  next?: string | string[];  // single next node, or array of choices for agent to pick
  reject_next?: string;      // gate only — path taken if user rejects at this gate
}
```

**`type` behavior:**
- `"agent"` — plugin injects the prompt, agent executes, calls `next_step` when done
- `"gate"` — plugin injects the prompt (approval/review request); agent calls `next_step({ next: "approve" | "revise" | ... })` based on user response; `reject_next` is the fallback path

**`next` behavior:**
- Single string → plugin auto-advances to that node; `next` arg in `next_step` is ignored
- Array of strings → agent MUST call `next_step({ next: "<choice>" })` with a valid choice; plugin throws if missing or invalid

### PlanDag (immutable definition)

```typescript
interface PlanDag {
  schema_version: "1.0";
  id: string;
  session_type: string;      // e.g. "plan-generic", "plan-debug", "execution"
  description?: string;
  entry: string;             // id of the first node to execute
  nodes: Record<string, DagNode>;
}
```

---

### DagSessionState (per-session runtime file)

```typescript
// One file per active session: .opencode/dag-state/<session-id>.json
interface DagSessionState {
  dag_id: string;
  status: "running" | "waiting_gate" | "complete" | "failed";
  current_node: string;
  started_at: string;   // ISO 8601
  updated_at: string;   // ISO 8601
}
```

**Rationale for per-session files:**
- Zero write contention between concurrent sessions (each session writes only its own file)
- Trivially atomic (single-file read/write per session)
- GC is trivial: archive to OMEGA Memory on completion, delete the file

## `next_step` Tool Behavior

```typescript
next_step({ next?: string })
```

Plugin implementation:
1. Read `.opencode/dag-state/<context.sessionID>.json`
2. Look up `current_node` in the plan DAG
3. If `node.next` is a single string → advance to that node, `next` arg ignored
4. If `node.next` is an array → `next` arg required; throw if missing or not in array
5. Inject next node's prompt via `ctx.client.session.prompt({ noReply: true, parts: [{ type: "text", text: <prompt content> }] })`
6. Update `dag-state/<session-id>.json` with new `current_node` and `updated_at`
7. If next node is `null` / no `next` field → set status `"complete"`, archive to OMEGA Memory, delete state file
8. Return: `"Step '<node-id>' complete. Advancing to '<next-node-id>'."` (or completion message)

## File Conventions

### Global planning assets (session-type DAGs)
```
~/.config/opencode/planning/
  plan-generic/
    plan.json
    prompts/
      gather-context.md
      analyze-requirements.md
      draft-plan.md
      review-gate.md
      finalize.md
  plan-debug/
    plan.json
    prompts/
      ...
  plan-collaborative/
    plan.json
    prompts/
      ...
```

### Session-specific plans (generated by planning sessions)
```
.opencode/session-plans/
  <plan-name>/
    plan.json
    prompts/
      <step-name>.md
```

### Runtime state
```
.opencode/dag-state/
  <session-id>.json   ← one file per active session
```

## Design Constraints

- **No output capture in `next_step`** — prompts instruct the agent where to write notes (e.g., "Write findings to `.opencode/session-plans/<name>/notes/step-N.md`")
- **No model_tier in schema** — primary agent cannot control model selection; this lives in agent configuration
- **No agent field in schema** — agent delegation lives in the prompt `.md` file
- **No parallel node type** — parallelism is expressed in a single node's prompt (e.g., "Dispatch 3 ContextScout agents in parallel via Task tool")
- **GC via OMEGA** — completed sessions archived immediately; no time-based cleanup
